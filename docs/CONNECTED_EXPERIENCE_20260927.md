# Connected capability experience — 27 September 2026

## Product problem
The original first viewport buried the primary action beneath a very long headline. Internal architecture, validation protocol names and commercial roadmap language competed with the student's immediate task. The graph-native matching engine existed, but users mainly encountered long textual explanations.

## Implemented approach
- Arabic-first, bilingual landing with a shorter value proposition, visible upload entry, adjacent local-processing assurance and a sample-report link.
- Interactive network generated from the existing Person360 matching output. Select evidence, capability, person, goal and pathway nodes to understand their relationships. The landing uses a clearly marked synthetic profile.
- In-product decision guide with structured questions. Answers come from the current rules and graph; there is no external LLM call or invented market information.
- Development plan prioritizing required evidence gaps, then contextual development suggestions. A downloadable plan does not create evidence, change judgments or promise employment.
- Review access from the dashboard and guide. Consistency checks gate incomplete rows, duplicate canonical course codes and invalid grades; manual changes retain self-declared provenance.
- Optional preferences can be cleared to “Undecided / prefer not to answer.” The product explains which dimensions currently influence contextual explanations.
- The doctoral research connection is described as transfer of a semantic-network design pattern, not transfer of empirical validity from another domain.

## Validation boundaries
- Existing rules, graph provenance, encryption, persistence, consent and static-route tests remain part of the regression suite.
- New tests cover invalid grades, code normalization, duplicate detection, source inspection, graph node overlap, Arabic/English rendering, selected-target answers, plan export and no mutation of evidence by plan generation.
- Automated accessibility checks do not establish full WCAG conformance. Assistive-technology and real-student usability studies are still required.
- No institutional document authentication, live jobs/catalog, project verification, or multi-user advisor backend is introduced.
- Keep proprietary occupational-taxonomy implementations private and existing public feature flags disabled.

## Competition gates still requiring real evidence
Pilot the journey with 10–15 target students. Measure first-result completion, correction errors, return visits and whether students can explain why a pathway was shown. Conduct independent matching and transcript-extraction validation before making accuracy claims. Real institution-approved mappings, actual opportunity data, and authorized institutional workflows remain necessary for a production competitive claim.
